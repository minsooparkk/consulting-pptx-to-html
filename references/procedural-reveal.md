# 절차별 누적 등장

절차를 순서대로 보여 달라는 요청에 사용한다. 선택한 슬라이드의 실제 읽는 순서와 객체를 확인해 매핑한다. 번호가 있다는 이유만으로 비교표나 목차를 절차로 바꾸지 않는다. 문구·좌표·서식은 유지한다.

## 적용

먼저 일반 변환으로 HTML을 만들고, 해당 슬라이드의 `data-object-id`와 화면을 함께 확인한다. 한 단계의 번호·제목·설명·배경·구분선을 묶고, 단계 사이 화살표는 도착 단계에 포함한다. 제목·Header·Footer는 고정한다. 여러 단계에 걸친 공통 선은 고정 객체로 둘 수 있다.

```text
python scripts/convert.py input.pptx -o preview.html
python scripts/convert.py input.pptx -o output.html --procedure-manifest procedures.json --procedure-interval-ms 300
```

- `--procedure-manifest`: UTF-8 JSON 파일. 아래 `slides` 형식을 사용한다.
- `--procedure-interval-ms`: 단계 시작 사이의 간격인 양의 정수. 기본 **300ms**, 사용자가 지정한 값이 우선이다.
- 첫 단계 시작 지연은 150ms, 등장 효과는 420ms다. 기본 간격에서는 앞 단계의 효과가 끝나기 전에 다음 단계가 시작할 수 있다.
- `--motion auto`가 기본이다. 절차 매핑과 `--motion none`을 함께 지정하면 오류다.
- 매핑하지 않은 슬라이드는 기존 자동 등장 방식과 약 920ms의 전체 표시 시간을 유지한다.

## 매핑 형식

최상위 `slides` 배열의 각 항목은 다음 필드를 사용한다.

| 필드 | 의미 |
|---|---|
| `slide` | 생성 HTML의 1부터 시작하는 슬라이드 번호 |
| `groups` | 실제 표시 순서의 단계 배열. 각 단계에 `label`과 객체 ID 배열 `ids` 지정 |
| `conclusionIds` | 선택 사항. 모든 단계 뒤에 함께 표시할 결론 배경·장식·텍스트의 ID |
| `staticIds` | 선택 사항. 처음부터 표시할 객체를 명시하는 ID 배열. 동적 그룹에 포함되지 않은 나머지 객체도 처음부터 표시됨 |

`label`은 매핑을 검토하기 위한 이름이며 슬라이드 문구를 바꾸지 않는다. `slides`, `groups`, 각 그룹의 `ids`는 비어 있으면 안 되고, `label`도 빈 문자열을 허용하지 않는다. ID는 생성된 HTML의 실제 값을 사용한다. 추정한 Google 도형 이름이나 DOM 나열 순서로 단계를 정하지 않는다. 같은 객체를 여러 단계·결론·고정 목록에 중복 배정하지 않는다. 원본 PPTX를 수정했다면 재변환 후 ID와 배치를 다시 확인한다.

부모 도형 그룹을 동적으로 지정하면 자손도 함께 표시된다. 동적 부모와 자식을 따로 중복 지정하거나, 그 아래 자식을 `staticIds`로 지정하지 않는다. 존재하지 않는 슬라이드·ID, 다른 슬라이드의 ID, 중복과 모순된 매핑은 출력 전에 오류로 처리한다.

다음은 저장소의 공개 샘플에서 4번 슬라이드의 세 단계를 매핑한 예시다. 실행 가능한 전체 파일은 [examples/sample.procedures.json](../examples/sample.procedures.json)을 사용한다. 실제 자료에는 해당 HTML에서 확인한 ID를 사용한다.

```json
{
  "slides": [
    {
      "slide": 4,
      "groups": [
        {
          "label": "첫 번째 단계",
          "ids": ["s004_slide_5", "s004_slide_6", "s004_slide_7", "s004_slide_8"]
        },
        {
          "label": "두 번째 단계",
          "ids": ["s004_slide_9", "s004_slide_10", "s004_slide_11", "s004_slide_12"]
        },
        {
          "label": "세 번째 단계",
          "ids": ["s004_slide_13", "s004_slide_14", "s004_slide_15", "s004_slide_16"]
        }
      ],
      "conclusionIds": ["s004_slide_17", "s004_slide_18", "s004_slide_19"]
    }
  ]
}
```

## 실행과 정리

각 단계가 나오면 앞 단계는 남아 있고, 결론은 마지막에 추가된다. JavaScript 타이머가 단계별 대기 상태를 직접 해제한다. 각 효과와 전체 순서가 끝나면 애니메이션·대기 클래스를 제거해 모든 내용을 일반 표시 상태로 남긴다. CSS 지연 애니메이션의 완료에만 의존하지 않는다.

슬라이드를 떠나거나 편집·검사·인쇄·모션 감소 상태로 바뀌면 진행 중 타이머와 숨김 상태를 정리한다. 탭 전환이나 페이지 복원 후에도 내용이 숨은 채 남지 않게 한다. 저장할 때는 복제 문서에서 일시적인 대기·애니메이션 상태를 제거하고 매핑·문구·글꼴은 보존한다. 저장본을 다시 열면 해당 슬라이드의 순서를 새로 시작한다.

## 검수

구조 검사와 실제 시간에 따른 동작 검사를 구분한다. 브라우저 API를 사용할 수 있는 범위에서만 검수하고, 실행하지 못한 항목은 미실시로 남긴다.

1. 매핑한 슬라이드의 모든 ID가 해당 슬라이드에 존재하고 중복이 없는지 확인한다. 단계 순서와 도착 화살표, 고정 제목·Header·Footer를 화면과 대조한다.
2. 평상시 모션 설정에서 슬라이드에 진입하고 실제 시간이 흐르도록 둔다. 초기·중간·최종 화면과 경과 시간을 기록한다. 다음 단계가 나타나도 앞 단계가 사라지지 않아야 한다. 간격을 조절했다면 실제 시작 간격도 확인한다.
3. 마지막 단계와 결론이 모두 나온 뒤 대기·애니메이션 상태가 정리됐는지 확인한다. 이때의 원본 배치·문구와 PowerPoint 렌더를 대조한다. 기본값에서 본문 네 단계와 결론 한 묶음의 효과 종료 시점은 진입 후 약 1.77초이며, 상태 정리 확인에는 약간의 여유를 둔다.
4. 진행 중 다른 슬라이드로 이동했다가 돌아오기, 탭 전환·복원, 모션 감소, 편집·인쇄를 확인한다. 진행 중 저장한 HTML을 다시 열어 내용 누락 없이 순서가 다시 실행되는지도 확인한다. 선택하지 않은 슬라이드의 기존 동작을 함께 점검한다.

`Animation.finish()`, `currentTime` 변경, 플레이어의 `clear()` 호출, 애니메이션 비활성화로 만든 화면을 자동 등장 완료의 증거로 사용하지 않는다. 이런 조작은 정적인 배치 검사에는 사용할 수 있지만, 실제 시간 흐름 검사를 대신하지 않는다. 편집·인쇄·모션 감소 검사를 통과한 사실도 평상시 순차등장 검사를 대신하지 않는다.

보고서의 `procedural_reveal`에서 선택 슬라이드와 단계별 설정, 최대 표시 완료·상태 정리 시간을 확인한다. `browser_verified: false`는 생성 시점에 실제 브라우저 동작이 아직 확인되지 않았다는 뜻이다. 선택 브라우저 회귀 실행 방법은 [README의 회귀 테스트](../README.md#회귀-테스트)를 따른다.
